📌 Описание проекта

В рамках итоговой работы по модулю «Защищённый контур» был проведён 
анализ защищённости корпоративного приложения, предназначенного для обмена 
корпоративной информацией, включая персональные данные клиентов и коммерческую тайну.

Заказчик: Компания Х  
Разработчик: Неизвестен (OVA-образ поставлен «из коробки»)  
Исполнитель: Специалист по информационной безопасности  
Цель: Проверка реальной защищённости приложения и выявление 
несоответствий требованиям нормативных документов (ФСТЭК №21).

🛠️ Пошаговое выполнение работы

1. Развертывание виртуальной машины

1.1 Импорт OVA

```bash
# В VirtualBox: Файл → Импорт конфигураций... → выбрать sk.ova
# Настройки оставить по умолчанию
# После импорта добавить Адаптер 2 → Внутренняя сеть → intnet
```

1.2 Первичный вход

```bash
# Вход в ОС
system / system (сменить пароль)

# Проверка IP-адресов
ip a
```

Результат:
| Интерфейс | IP-адрес | Назначение |
|-----------|----------|------------|
| `enp0s3` | `10.0.2.15` | NAT (интернет) |
| `enp0s8` | `192.168.0.1` | Внутренняя сеть |

---

2. Проверка приложения

2.1 Проверка сервиса

```bash
sudo systemctl status sk.service
```

**Результат:** `active (running)`

2.2 Проверка порта

```bash
sudo ss -tulpn | grep 8888
```

Результат: `LISTEN 0.0.0.0:8888`

2.3 Чтение пароля администратора

```bash
cat /opt/sk/password.txt
```

Результат: `f38e440d-ac0d-480f-b674-81b8e7aa45d6`

---

3. Настройка Kali

```bash
# Назначение IP в той же сети
sudo ifconfig eth0 192.168.0.2 netmask 255.255.255.0 up

# Проверка связи с сервером
ping 192.168.0.1
```

Результат: Связь установлена.

---

4. Сканирование

```bash
# Сканирование портов и версий
nmap -sV -p- 192.168.0.1
```

Результат: Порт `8888` открыт (приложение "Защищенный контур").

5. Поиск и эксплуатация уязвимостей

5.1 Command Injection (CWE-20)

```bash
curl "http://192.168.0.1:8888/api/ping?host=127.0.0.1;id"
```

Результат: `404 Not Found` — эндпоинт не существует.

Вывод: Command Injection не обнаружена.

---
5.2 Path Traversal (CWE-22)

```bash
curl "http://192.168.0.1:8888/api/file?path=../../../../etc/passwd"
```

Результат: `404 Not Found` — эндпоинт не существует.

Вывод: Path Traversal через API не обнаружен.

---

5.3 Проверка страниц и API

```bash
# Проверка существующих страниц
curl -I http://192.168.0.1:8888/clients
curl -I http://192.168.0.1:8888/admin
curl -I http://192.168.0.1:8888/documents
curl -I http://192.168.0.1:8888/login
curl -I http://192.168.0.1:8888/register
```

Результаты:

| URL | Статус |
|-----|--------|
| `/clients` | `303 See Other` → `/login.html` |
| `/admin` | `404 Not Found` |
| `/documents` | `404 Not Found` |
| `/login` | `405 Method Not Allowed` |
| `/register` | `404 Not Found` |

Вывод: Страница `/clients` существует и перенаправляет на вход.

---

5.4 Перехват трафика (CWE-319)

```bash
sudo tcpdump -i eth0 -A port 8888
```

Что было обнаружено:
- Пароль передается в открытом виде
- Токен сессии передается в Cookie в открытом виде
- Протокол HTTP (не HTTPS)

Доказательство:
```http
POST /login.html HTTP/1.1
Host: 192.168.0.1:8888
Cookie: token=28806649

username=admin&password=f38e440d-ac0d-480f-b674-81b8e7aa45d6
```

---

5.5 XSS (CWE-79)

```html
<script>alert(1)</script>
```

Результат: Приложение экранирует HTML-спецсимволы (`&lt;script&gt;alert(1)&lt;/script&gt;`).

Вывод: XSS не обнаружен.

---

5.6 CSRF-защита (CWE-352)

Проверка HTML-кода: В формах отсутствуют CSRF-токены.

```html
<form action="/administrate/delete" method="post">
    <input type="hidden" name="login" value="admin">
    <button>Удалить</button>
</form>
```

Вывод: CSRF-защита отсутствует.

---

5.7 Брутфорс (CWE-307)

Проверка: Нет ограничения количества попыток входа.

Вывод: Приложение уязвимо к брутфорсу.

6. Анализ соответствия ФСТЭК №21

6.1 Меры ИАФ (Идентификация и аутентификация)

| Мера | Требование | Реальность | Статус |
|------|------------|------------|--------|
| ИАФ.1 | Идентификация пользователей | Пароль в открытом виде | ❌ |
| ИАФ.4 | Управление средствами аутентификации | Пароль не хеширован, нет смены | ❌ |
| ИАФ.5 | Защита обратной связи при вводе | Передача по HTTP | ❌ |

6.2 Меры УПД (Управление доступом)

| Мера | Требование | Реальность | Статус |
|------|------------|------------|--------|
| УПД.1 | Управление учетными записями | Только admin (нет управления) | ❌ |
| УПД.2 | Разграничение доступа | Нет ролей, все имеют все права | ❌ |
| УПД.6 | Ограничение неуспешных попыток | Не реализовано | ❌ |
| УПД.11 | Запрет действий до аутентификации | Доступ к API без логина | ❌ |

6.3 По защите коммерческой тайны

Требование: разграничение доступа к КТ встроенными средствами приложения.

Реальность: разграничение доступа отсутствует. Документы доступны всем авторизованным пользователям.

Статус: ❌ Критическое нарушение
